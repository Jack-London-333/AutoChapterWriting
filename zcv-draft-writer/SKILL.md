# ZCV Draft Writer

Use this skill when writing or revising a `turn-N/draft-turn-N.md` manuscript that will later be processed by `zcv-app`.

This skill is only for draft writing rules and a short orientation to the app workflow. The current app, `zcv-app`, owns Zotero matching, LaTeX generation, citation-map updates, verification queues, Codex PDF verification workers, and generated reports.

## Hard Boundaries

- When the user asks to edit a draft, modify only the requested `turn-N/draft-turn-N.md` unless the user explicitly asks for another file.
- Do not edit `citation-map-turn-N.json`, `latex-manuscript/`, `verification-evidence/`, `import-reports/`, `runtime/`, queues, worker outputs, or app state while doing a draft-writing task.
- Do not use the deprecated `zotero-citation-verification` workflow as the source of truth. Treat `zcv-app` as the active workflow.
- Never invent a DOI or bibliographic detail. If adding a new Reference, verify the DOI from an authoritative source such as the DOI page, publisher page, or official journal page.

## Turn And Key Rules

1. Infer the current turn from the draft path, for example `turn-004/draft-turn-004.md` means the current turn is `004`.
2. Body citations must use Markdown citation syntax:
   - One citation: `[@citekey]`
   - Multiple citations: `[@citekey1; @citekey2]`
   - Do not use numeric citations such as `[1, 2]`.
3. A checked key is a real Zotero Better BibTeX key that already corresponds to a Zotero item.
4. An unchecked key is a temporary key and must be written as `@turn-N-k`, where `N` is the current three-digit turn and `k` is an integer assigned by first appearance in the current draft body.
5. For `turn-004/draft-turn-004.md`, new unchecked keys must be `@turn-004-1`, `@turn-004-2`, etc. Do not use a previous turn prefix.
6. Reuse existing checked keys when citing an item that is already present in the draft References.
7. If a new source is not yet confirmed as a Zotero item with a Better BibTeX key, use the next available temporary key for the current turn.
8. Do not rename Better BibTeX keys generated by Zotero.

## Empty Draft Rules

- If `draft-turn-N.md` is empty or contains only whitespace, create a complete ZCV draft structure instead of appending fragments.
- The minimum structure is one or more manuscript sections, usually starting with `## Introduction`, followed by a final `## References` section.
- For `turn-001/draft-turn-001.md`, newly introduced sources normally use temporary keys such as `@turn-001-1`, `@turn-001-2`, assigned by first body appearance, unless the user explicitly provides real Zotero Better BibTeX keys.
- For any other empty `draft-turn-N.md`, use the current turn prefix for new temporary keys, such as `@turn-004-1`, `@turn-004-2`.
- Body prose must use Markdown citation syntax, for example `[@turn-001-1]` or `[@turn-001-1; @turn-001-2]`.
- Every body citation key must have exactly one matching entry in `## References`, and every Reference entry must be cited in the body.
- Do not create uncited References.
- Each Reference entry should use the standard form `[@key] Author, “Title”, *Venue*, year, [DOI](https://doi.org/...)`.
- Verify every DOI before writing a Reference entry. If a needed DOI cannot be verified, stop and report the missing source instead of inventing metadata.

## Draft Writing Workflow

1. Read the target `draft-turn-N.md` before editing.
2. If this is a next-round draft, also read `turn-(N-1)/verification-evidence/verification-turn-(N-1).md` when available. Use it to avoid repeating unsupported claims and to strengthen weakly supported claims.
3. When using a previous-turn verification file, also inspect the linked evidence images under `turn-(N-1)/verification-evidence/images/` whenever a claim is being kept, strengthened, weakened, split, or rewritten based on verification evidence.
4. Treat the Markdown explanation in `verification-turn-(N-1).md` as a guide, but treat the screenshot itself as the evidence boundary. Pay special attention to claims marked `较强支持`, `间接支持`, `不充分支持`, or `不支持` before deciding whether to keep, narrow, split, or remove the claim.
5. Add or revise prose at claim level. Prefer sentences whose cited part can be verified independently.
6. If one sentence contains multiple independent claims supported by different references, split it or place citations so each claim segment is clear.
7. When adding a new source, verify its DOI first. If the DOI cannot be verified, do not add the source as a formal Reference unless the user explicitly asks to keep a placeholder.
8. Add a matching `## References` entry for every new citation key used in the body.
9. Remove a Reference only if its key is no longer used in the body after the edit.

## Line Layout Rules

- Markdown draft body should normally use one complete sentence per physical line.
- 这里的“一句话”按完整句末标点判断，主要包括句号、问号和感叹号。
- Consecutive sentence lines can still belong to the same paragraph. Do not add blank lines between sentences unless starting a new paragraph.
- Do not force a line break at every citation marker or claim segment.
- If one complete sentence contains multiple parallel claims and multiple citations, keep it on one line, for example: `实现超导有多种方案，包括技术A[@key1; @key2]、技术B[@key2; @key3; @key4]以及技术C[@key5; @key6; @key7]。`
- If a sentence is too long and contains several relatively independent assertions, prefer rewriting it into multiple complete sentences instead of mechanically breaking the line inside one sentence.
- This line layout rule supports readability, diffs, local LLM rewrites, and human review. It does not replace verification-stage claim segmentation.

## Using Zotero For Draft Revision

- If a draft sentence cites an existing real Better BibTeX key and the wording feels uncertain, too broad, too strong, or possibly mismatched with the cited source, use Zotero when available to inspect the referenced item before rewriting.
- Prefer looking up the Zotero item by its Better BibTeX key from the draft.
- If the Zotero item has a PDF attachment, read the relevant original text, abstract, conclusion, figure caption, or nearby passage before strengthening or narrowing the sentence.
- Do not infer detailed support only from the citation key, title, or Reference line when the statement is specific or potentially risky.
- If Zotero has no PDF attachment, say that the item has no PDF and write conservatively. Do not imply that the original PDF was checked.
- Temporary keys such as `@turn-N-k` are not yet matched Zotero items, so they cannot be checked through Zotero by BibTeX key. For those, rely only on verified DOI/source information or keep the wording conservative until zcv-app matching and PDF verification are available.
## Reference Rules

- Every body citation key must have exactly one corresponding entry in `## References`.
- Every `## References` key must be used in the body.
- Reference entries use this key prefix form: `[@key] ... [DOI](https://doi.org/...)`.
- Add every newly written Reference entry at the end of `## References`. Do not insert new entries into the middle of the existing list.
- If multiple new temporary keys are added in one edit, append their Reference entries at the end in first body-appearance order.
- Do not reorder existing References for chronology, topic, or visual tidiness. Existing entries should stay in place unless their key is no longer used in the body.
- A Reference entry for a temporary key keeps the temporary key until `zcv-app` matches it to Zotero.
- A Reference entry for a checked key should preserve the real Better BibTeX key and use readable bibliographic text.
- Each Reference entry should include a DOI link. If the publication truly has no DOI, stop and ask the user before adding it.

## zcv-app Orientation

`zcv-app` is the active local application for the rest of the workflow. Its state is stored in `zcv-app/state/app-state.json`, including the workspace, current turn, collection name/key, and app preferences.

After a draft edit, the user normally runs the app to:

1. Parse the draft and check citation/Reference consistency.
2. Recheck Zotero by DOI and update `citation-map-turn-N.json`.
3. Generate `latex-manuscript/main-turn-N.tex` and `references-turn-N.bib` from matched Zotero/BibTeX data.
4. Build verification tasks under `verification-evidence/`.
5. Run Codex PDF verification workers and apply `result.json` outputs into `verification-turn-N.md`.

The draft writer does not perform those app-owned steps unless the user separately requests app work.

## Preflight Checks Before Finishing

Before reporting completion, check the draft logically:

- The body citation key set and the `## References` key set are identical.
- Temporary keys use the current turn prefix only.
- Temporary keys are ordered by first body appearance.
- Newly added or changed References have verified DOI links.
- Existing checked Better BibTeX keys have not been rewritten.
- Only the intended `draft-turn-N.md` was edited for a draft-writing request.

In the final response, mention any remaining temporary keys because `zcv-app` still needs to match them to Zotero.
